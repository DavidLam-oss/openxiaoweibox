## Skill 是怎么跟你「对话」的

很多人对 Skill 有个误解：以为它是一个按键，按下去就自动吐一篇文章出来。

不是的。

它更像一个需要你指挥的团队。你给方向，它出初稿。你挑毛病，它改。你再挑，它再改。几次来回之后，文章才能到你满意的程度。

这套对话机制，是 Skill 的核心。下面我用这一篇文章的诞生过程来演示。

---

## 第一轮：我给方向，它出策划案

这篇文章的起点是：我前阵子写了入门 40（送 Skill 的那篇），后来又写了入门 68（注册公众号），然后我想补一篇——拿了 Skill 之后，怎么实操？

我把这个想法给到 wechat-writer Skill，同时让它去阅读之前的文章：入门 40 的文章、入门 68 的文章、以及两个 Skill 的说明书（SKILL.md）。

![Obsidian 入门 69：拿到 Skill 之后，怎么用它写完一篇文章 - 截图 1](/images/posts/Obsidian%20%E5%85%A5%E9%97%A8%2069%EF%BC%9A%E6%8B%BF%E5%88%B0%20Skill%20%E4%B9%8B%E5%90%8E%EF%BC%8C%E6%80%8E%E4%B9%88%E7%94%A8%E5%AE%83%E5%86%99%E5%AE%8C%E4%B8%80%E7%AF%87%E6%96%87%E7%AB%A0/CleanShot%25202026-07-02%2520at%252000.37.06.webp)


它读完这些材料之后，没有直接写正文。它先出了一份 `01_Plan.md`，里面包含：

- **素材摘要**：它读了我的旧文章和 Skill 说明书，提炼出了关键信息
- **选题质检卡**：三个维度打分——好奇感强、信息增量强、共鸣感强
- **人机边界卡**：哪些是我亲身经历不能编的，哪些是它可以辅助的
- **核心论点**：它认为这篇文章应该主张「Skill 不是拿来收藏的，是拿来跑流程的」
- **结构大纲**：从开头到结尾的推进路线，每一段回扣什么论点

这些都在策划案里写清楚了。

⛔ **然后它停下来了。**

![Obsidian 入门 69：拿到 Skill 之后，怎么用它写完一篇文章 - 截图 2](/images/posts/Obsidian%20%E5%85%A5%E9%97%A8%2069%EF%BC%9A%E6%8B%BF%E5%88%B0%20Skill%20%E4%B9%8B%E5%90%8E%EF%BC%8C%E6%80%8E%E4%B9%88%E7%94%A8%E5%AE%83%E5%86%99%E5%AE%8C%E4%B8%80%E7%AF%87%E6%96%87%E7%AB%A0/CleanShot%25202026-07-02%2520at%252000.35.36.webp)


它不会自作主张往下写。它在等我确认。

我读了那份策划案，觉得方向对，说了一句「进 stage2 吧」。

它才开始写初稿。

![Obsidian 入门 69：拿到 Skill 之后，怎么用它写完一篇文章 - 截图 3](/images/posts/Obsidian%20%E5%85%A5%E9%97%A8%2069%EF%BC%9A%E6%8B%BF%E5%88%B0%20Skill%20%E4%B9%8B%E5%90%8E%EF%BC%8C%E6%80%8E%E4%B9%88%E7%94%A8%E5%AE%83%E5%86%99%E5%AE%8C%E4%B8%80%E7%AF%87%E6%96%87%E7%AB%A0/CleanShot%25202026-07-02%2520at%252000.37.46.webp)

## 第二轮：它写初稿，我来挑毛病

策划案通过之后，主笔冰清开始撰写。它参考策划案里定好的大纲，用我的语气写了一篇初稿。

写完之后，顾问罗永浩上场审了一遍，出了一份审校报告，打分 80/100，指出了几个问题：

- 彩蛋出现太突兀
- 有个多余逗号
- 整体内容太像入门 40 的重复

然后主编根据审校报告，出了一份修改指令。主笔按指令改出了 v2。

⛔ **然后又停下来。**

![Obsidian 入门 69：拿到 Skill 之后，怎么用它写完一篇文章 - 截图 4](/images/posts/Obsidian%20%E5%85%A5%E9%97%A8%2069%EF%BC%9A%E6%8B%BF%E5%88%B0%20Skill%20%E4%B9%8B%E5%90%8E%EF%BC%8C%E6%80%8E%E4%B9%88%E7%94%A8%E5%AE%83%E5%86%99%E5%AE%8C%E4%B8%80%E7%AF%87%E6%96%87%E7%AB%A0/CleanShot%25202026-07-02%2520at%252000.39.20.webp)


它把 v2 推给我，等我反馈。

我读了之后，觉得确实有个大问题：**中间那段写得太像入门 40 的重复了。**

我要的不是一个 Skill 功能的说明书：入门 40 已经写过那个了。我要的是呈现我们两个人之间的对话过程：我给了什么，它回应了什么，我又给了什么反馈，它又怎么调整。

所以我现在在这里，打下这些字。

这就是第三轮对话。

![Obsidian 入门 69：拿到 Skill 之后，怎么用它写完一篇文章 - 截图 5](/images/posts/Obsidian%20%E5%85%A5%E9%97%A8%2069%EF%BC%9A%E6%8B%BF%E5%88%B0%20Skill%20%E4%B9%8B%E5%90%8E%EF%BC%8C%E6%80%8E%E4%B9%88%E7%94%A8%E5%AE%83%E5%86%99%E5%AE%8C%E4%B8%80%E7%AF%87%E6%96%87%E7%AB%A0/CleanShot%25202026-07-02%2520at%252000.40.00.webp)

## 第三轮：我给了反馈方向，它在改

你正在读的这一版，就是第二轮 feedback 的结果。

它的结构不再按「Stage 1 做什么、Stage 2 做什么」来讲，而是按「我们之间的几次来回」来讲：

- **第一轮**：我给了想法 → 它出了策划案 → 我确认 → 它进入下一阶段
- **第二轮**：它写了初稿 → 审校改了问题 → 我读了发现方向偏了 → 给了新feedback
- **第三轮**：它按我的反馈重写了 → 正在等你读到这

每一轮之间都有一条清晰的界线：**AI 提效，人做决策。**

## 配图环节同理

等这篇文字定稿之后，我会喊 wechat-director 出来。

它不会直接出图。它会先读一遍文章，出一份 Storyboard.md，包含封面图、侧边栏图、内文配图的 Prompt 方案。

⛔ **它停下来，等我确认分镜方案。**

## 你真正要做的事：读、判断、确认

回过头看，Skill 在整个流程里做的事是：读材料、出方案、写初稿、审校、改错、生图。

而你做的事是：**读方案、判断对错、做决策、给反馈。**

需要你拍板的事情总共也就四件：

1. **策划案**：方向对不对？大纲有没有漏掉你想说的？
2. **正文**：读起来像你吗？有没有不该说的？
3. **标题**：四个方案里你最想点哪个？
4. **分镜**：配图方向合不合你心意？

都是判断类的事：不是创造类的事。AI 做创造，你做判断。各司其职。

---

入门 40 送了你工具，入门 68 给了你场地，入门 69 带你跑了一圈。

作业很简单：**把你想写的那个想法，丢给你的 Skill。看它出什么策划案，看完再决定要不要往下写。**

需要你做的事，没有你想象的那么多。
